## 环境与复现

- Java 21、PostgreSQL 18.6、真实 Docker；测试使用专用数据库 `mojie_cs_test`，集成用例各自创建并删除独立 schema。
- 模型接口测试启用本机 HTTP 测试服务，不访问生产模型。真实模型另使用独立数据库 `mojie_cs_live` 与独立文件根；恢复到 `mojie_cs_restore` 和另一文件根。
- Python 固定镜像 `python@sha256:a3ab0b966bc4e91546a033e22093cb840908979487a9fc0e6e38295747e49ac0`，实测 Python 3.11.15。
- Node 固定镜像 `node@sha256:43ac6c60b8f89723f746e8a92ce91abd5017e627ce1ddfe4238355d3a30b772c`，实测 Node.js 22.23.3。
- 模型和数据库凭据通过环境注入，不写入模型请求快照、验证 JSON 或本文。

后端复现需设置专用 `MOJIE_TEST_JDBC_URL`、`MOJIE_TEST_DB_USER`、`MOJIE_TEST_DB_PASSWORD`，并设置 `MOJIE_TEST_LOCAL_HTTP=1`、`MOJIE_TEST_EXECUTOR_URL=http://127.0.0.1:8091`，然后运行 `mvn -f backend/pom.xml verify`。执行器启动方法见 [执行器说明](../../executor/README.md)。浏览器测试在同一专用数据库运行 `npm --prefix web run test:e2e`；它会构建后端，不能与 Maven 测试同时使用同一个 `backend/target`。

## 真实模型与失败样本

使用实际配置的 `deepseek-ai/DeepSeek-V3.2`。完整记录见 [最终实测记录](conversation-skills-live-2026-10-02.json)；最初样本见 [首次实测记录](conversation-skills-live-first-2026-10-02.json)。失败执行和中间结果均保留。

已核对：第二轮能引用“林舟怕火”；第三轮首次发现并加载报告 Skill；正文、参考、已保存章节和人物设定逐步进入请求；章节修改产生候选并独立采纳，正式正文由“他游到了对岸”改成“他沿桥走到了对岸”；另一独立对话使用明确指定的旧 Skill 版本，通过真实 Python 生成报告并下载核对正文。

第三轮虽然加载了正确 Skill，模型反复省略脚本 `inputs`，造成真实 `FileNotFoundError`，最终给出文字分析而没有交付下载文件。该 Run 的技术终态为 SUCCEEDED，并不表示报告需求已经满足。仅加强说明后旧历史仍有同类失败；将工具 schema 的 `inputs` 设为必填（无输入时传 `[]`）后，在新的独立对话完成真实产物闭环。模型最初还错误地声称没有保存对话信息的机制；后续轮次的真实输入与回答证明历史已送达。这些样本说明模型陈述和遵循指导的质量仍需逐例评估。

记录中的 `technicalAssertions` 是指定技术路径的断言，不代表全部尝试成功，也不代表文学质量或全部真实模型评估材料已经签收。未在真实模型专项覆盖的材料包括两个相似描述 Skill、同 Run 第二次发现另一 Skill、真实长历史压缩后续聊，以及依赖不可用时的最终答复质量。

## 独立恢复

[恢复记录](conversation-skills-restore-2026-10-02.json) 保存实际结果。将 PG dump 和完整文件根恢复到独立数据库与目录后，按清单校验 5 个包/产物文件；恢复时有 2 个对话、12 条展示消息、45 个逻辑请求快照、1 个有效产物。

启动独立恢复服务后验证：旧版本 ZIP 导出与二进制内容、原产物下载、固定旧版指导送达，以及真实模型继续旧对话。继续后的回答仍引用林舟不会游泳、怕火。测试结束后停止测试服务；原运行环境未修改。恢复报告包含测试环境路径，不能将临时目录视为长期备份保留策略。
