普通正文搜索由 `api/routers/chapters.py → storage/services/chapter_service.py → storage/repos/chapter_repo.py` 实现。源码先按当前正文做不区分大小写的筛选，再逐行检查；上述大小写行为是实际 HTTP 观察。搜索不需要嵌入模型。它和本项目 `search_chapters` 的大小写、历史版本、游标和位置语义不同。

上游 **Agent 工具** `search_chapters` 是另一入口。`agent_runtime/tools/impls/chapter/search_chapters.py` 源码先读取 `default_embedding_model`，空值抛出 `ToolExecutionError`，随后检查索引状态并调用混合检索查询。这里是静态源码结论；本次没有真实模型会话，因此没有观察到该工具的运行错误或检索结果。

## 前端迁移依赖

上游 `WritingPage` 引用 `useVolumeTree`、`useCreateChapter`、`useNoteTree`、写作与标签 store、`AssistantSidebarHost`、路由参数和 App Shell；`main.tsx` 还初始化 QueryClient、主题、i18n、字体、鉴权/健康/设置、Socket.IO 和 tiktoken。Mojie 的 `web/src/main.jsx` 只挂载本项目工作台，`App.jsx` 通过 `api.js` 获取内容，`useRun.js` 订阅 SSE；迁移顺序和取舍见 [工程映射](../reference/engineering-map.md)。上游这些页面依赖是静态阅读结果，未逐一在浏览器操作。

## 未实测边界

PRD 要求的“Agent 读取上下文 → 受控编辑 → 记录和界面更新”、Agent 取消与页面刷新在参考容器中均未跑通：没有已配置 LLM，创建会话即被模型校验拒绝。因此不能把源码路径或 Mojie 模拟模型结果记作上游实测。Mojie 的确定性模拟模型、PostgreSQL 和 HTTP/SSE 证据另见 `docs/verification/`；真实模型五组输入、近 6000 码点和真实浏览器/Nginx 验收仍待完成。
