## 1. 目标与现状

### 1.1 产品目标

作者可以在作品下新建多个独立对话，在一个对话中持续讨论、查阅证据和提出章节修改建议。作者可以上传完整 Skill 包并管理版本；模型在任意聊天轮次，根据用户要求和任务进展发现适用 Skill，按需读取指导、参考文件，执行包内脚本并交付生成文件。

Skill 是可发现的任务指导与资源包。工具提供操作能力；Skill 指导工具的使用方法，不自行增加权限，也不保证模型完全遵循指导或文学判断正确。

### 1.2 当前代码核查

| 当前实现 | 对本功能的影响 |
| --- | --- |
| `AgentPanel` 提交作品、目标章、版本、指令和幂等键，没有对话 ID | 需要对话列表、消息输入与对话接口 |
| `AgentLoop.run()` 每次创建新消息列表，只加入当前初始输入 | 当前任务不继承历史，需要独立 ContextBuilder |
| `tb_agent_message`、模型输入序号按 Run 关联 | 已有执行记录可复用，输入引用需支持同一对话的历史 |
| 初始输入、系统提示和成功校验要求完整读取目标章 | 普通聊天需独立任务规则，目标章允许为空 |
| 每作品一个活动 Run，2 个执行线程、8 个排队名额 | 本期保留作品活动槽及全局容量，并增加对话顺序约束 |
| 两套模型适配器保留工具协议和提供方特有内容块 | 历史不能从界面文本或步骤摘要反向拼造 |
| 当前只有 PG 持久化卷，没有完整包存储和脚本执行器 | 需要新增文件卷与执行环境 |

核查来源：`backend/src/main/java/com/mojie/agent/loop/AgentLoop.java`、`backend/src/main/java/com/mojie/agent/runtime/RunScheduler.java`、`backend/src/main/java/com/mojie/agent/run/infra/JdbcRunAdmission.java`、`backend/src/main/java/com/mojie/agent/trace/infra/JdbcLoopTrace.java`、`web/src/features/agent/AgentPanel.jsx`、`deploy/compose.prod.yaml`。这些相对源码路径均以仓库根目录为起点。

### 1.3 术语

| 名称 | 定义 |
| --- | --- |
| Conversation／对话 | 一组连续用户消息、助手回复、上下文摘要和消息中的 Skill 引用 |
| Turn／轮次 | 一次已受理用户输入及其响应任务；失败、取消仍保留该轮记录 |
| Run／任务 | 响应一轮输入的执行单元，包含一次或多次模型请求和工具调用 |
| Skill 版本 | 一个发布后不可变的完整文件包，以版本 ID 和内容哈希定位 |
| 发现目录 | 当前 Run 可用 Skill 的名称、描述和读取位置，不包含全部正文 |
| 已加载 | Skill 指导已保存为实际输入内容；是否送达由模型输入引用确认 |
| 用户引用 | 用户在任务消息中明确指定 Skill，不形成对话级固定配置 |

## 2. 功能范围与用户场景

### 2.1 本次完整交付范围

| 必须交付 | 本次不包含 |
| --- | --- |
| 新建、切换、重命名独立对话；连续消息和刷新恢复 | 多人协作、消息分支、编辑历史后重放、运行中插入消息 |
| 每轮重新判断 Skill 适用性；用户消息引用与自动发现 | 多 Agent、Skill 自动下载市场、推荐算法和自动生成 Skill |
| 单 Markdown、ZIP、目录上传；完整文件树保存、预览与导出 | Git 自动同步、任意压缩格式、跨平台运行环境完全兼容 |
| Skill 启停、不可变版本、更新、回滚、逻辑删除 | 无条件支持任何脚本语言或自动安装任意依赖 |
| 正文与参考文件渐进加载；受限脚本执行与生成文件下载 | 在 Java 服务进程中直接执行上传代码、脚本直接写正式正文 |
| 历史压缩、输入追踪、版本隔离、包恢复与备份验证 | 服务重启自动续跑、任意外网访问、逐字输出 |

本表中的阶段可分批开发，但只有文本导入或只完成摘要发现不能作为完整功能验收通过。

### 2.2 必须覆盖的用户场景

1. 作者新建“人物讨论”对话，连续追问；再新建“大纲讨论”，后者不继承前者的消息、摘要和已加载 Skill。
2. 作者上传带 `references/`、`scripts/`、`assets/` 的 Skill，预览后启用；在第 3 轮提出匹配需求，模型此时才发现并加载。
3. 模型读完章节后发现还需要另一种检查方法，在同一 Run 的后续请求中加载另一 Skill。
4. 作者通过引用按钮或 `$` 在消息中明确指定 Skill，也可以不指定并由助手自行发现；设置中查看、管理和停用。
5. 作者更新 Skill 后，正在运行的任务保持旧版本；新任务发现新版，重试仍使用原任务的显式版本快照。
6. 对话变长后压缩旧历史，作者继续追问；当前必要的 Skill 指导和关键证据引用仍可恢复。
7. Skill 脚本生成报告或模板，作者下载；脚本失败时展示真实错误，正式章节不受影响。

## 3. 对话与章节行为

### 3.1 对话操作

- 对话归属于一个作品和服务端确定的作者。新建时默认标题为“新对话”，首次输入可生成简短标题；作者可重命名。
- 新建对话不复制其他对话的消息、摘要、固定选择、加载记录或工作目录。启用的个人 Skill 库仍可用于发现。
- 界面区分“新建对话”和“继续当前对话”；不得用修改前端 `runId` 代替新建持久化对话。
- 切换对话、章节或关闭页面不取消已受理 Run；刷新后按对话查询轮次及活动任务。
- 历史对话统一展示，无归档状态。活动任务期间拒绝重命名；继续发送仍受任务互斥和原模型配置兼容性校验约束。
- 本期不提供物理删除对话或修改已受理历史消息的入口。

### 3.2 输入与执行顺序

- 每次发送携带 `clientRequestId`、当前 `expectedConversationSeq`、本轮任务类型及可选章节目标。
- 单轮发送的用户输入、会话序号、Run、输入边界和活动槽在同一受理事务中提交。失败不得留下无执行归属的半条消息。
- 同一作者的幂等键约束沿用现有规则；摘要覆盖 conversation ID、历史边界、规范化输入、任务类型、章节版本和显式 Skill 选择。相同键不同内容返回冲突。
- 同一对话最多一个活动 Run；本期同时保留每作品一个活动 Run。其他对话可以浏览和准备输入，发送时显示作品正在执行任务，后端再次校验。
- 对话序号冲突返回 `CONVERSATION_VERSION_CONFLICT`，刷新后重发，不能悄悄基于旧历史创建分支。
- 本期不在活动 Run 中途接收用户追加消息。停止、等待终态后可以发送下一轮。
- 失败或取消保留输入与执行记录。重试引用原轮次和已提交输入，创建新 Run，不重复插入用户消息；模型历史不重复包含该输入。

### 3.3 本轮任务类型

| 类型 | 输入与成功条件 | 修改能力 |
| --- | --- | --- |
| `CHAT` | 作品范围内聊天；目标章可为空；存在有效最终回复 | 本轮不提供 `propose_edit` |
| `CHAPTER_REVIEW` | 目标章与 expectedVersion 必填；完整目标章结果必须进入最终请求 | 分析；本轮不提供 `propose_edit` |
| `CHAPTER_EDIT` | 同上；固定目标章基准正文和版本 | 允许一个候选稿；成功时发布建议，由作者独立采纳 |

用户可以在一轮输入前切换任务类型或章节。模型不能自行改变本轮目标与权限；普通聊天需要修改正文时，回复提示用户选择章节修改任务。

章节任务有未保存正文时仍需先保存。普通聊天可以发送，但只讨论已保存作品内容，界面明确当前草稿未提供给模型。切换编辑器章节不自动切换对话，不改变已经受理的任务目标。

每轮章节任务重新固定当前基准版本；不能因为历史中读过同章而跳过本轮完整读取。旧工具结果标记其历史版本。建议采纳、版本冲突、草稿保护与失败不发布候选规则继续有效。

## 4. 连续上下文与历史压缩

### 4.1 ContextBuilder 职责

每个 Run 在受理时固定历史边界、任务参数、模型/接口配置、工具 schema、Skill 目录及必要的版本引用。ContextBuilder 按顺序构造基础规则、任务规则、作品及目标元数据、发现目录、必要 Skill 指导、历史摘要、近期完整历史和当前输入。

上下文只引用所属对话中已提交且位于固定边界内的内容。历史消息保留工具调用/结果配对和提供方必须回传的协议块；界面最终回复、步骤摘要和 SSE 事件均不能替代原始协议。

每次模型请求持久化有序消息引用及有效输入快照，包含系统规则、工具定义、目录、合成上下文和摘要版本。快照覆盖逻辑模型请求，不保存鉴权头或密钥。Skill 文本通过带来源的指导片段注入，不赋予其修改基础规则的权限。

### 4.2 失败、取消与接口兼容

- 不把失败 Run 的未完成助手工具声明直接放入下一轮请求。上下文只能重用完整协议组；剩余记录保留供排查，下一轮可见对应用户输入和任务未完成标记。
- 终态只有最终回复作为本轮回答发布，中间计划文本不能冒充回答。
- 本期在一个对话中固定模型及接口类型；切换服务配置后旧对话仍显示原配置。旧配置不可用时返回 `CONVERSATION_MODEL_UNAVAILABLE`，允许作者新建对话使用当前配置，不暗中转换提供方特有协议块。
- 服务重启将旧活动任务标记失败并恢复展示，不继续执行；对话历史和固定 Skill 偏好保留，作者可重试或继续聊天。

### 4.3 历史压缩

连续聊天必须支持自动压缩，不要求用户在上下文满后只能新建对话。原始消息永不被摘要覆盖。

- 使用与模型请求预检相同的输入预算口径。有效输入达到可用输入预算的 70% 时，在无未完成工具协议组的边界发起压缩；组装后仍超过上限则明确返回 `CONTEXT_TOO_LARGE`。
- 可用输入预算扣除最大输出及协议预留，并同时满足应用字符上限和提供方上下文窗口。当前 UTF-8 字节保守估算仍须标为估算，不作为精确 tokenizer 计数。
- 保留当前用户输入、近期完整轮次和当前必要指导；旧完整轮次可总结，记录覆盖起止消息、来源摘要版本、模型配置和结果。
- 摘要保存用户要求、重要结论、未解决事项、章节/设定版本引用和 Skill 版本；不把推测改写为已验证事实，不宣称未进入模型请求的资料已读。
- 压缩后检查必要指导是否仍在有效输入；只剩 Skill 名称时，须按固定版本重新加载正文。二进制资产和大型文件不塞进摘要。
- 压缩作为本轮可追踪的模型阶段，消耗模型次数、时间和上下文预算，压缩结果提交后才能使用；失败返回 `CONTEXT_COMPACTION_FAILED`，不得悄悄截断历史。

## 5. Skill 管理与上传

### 5.1 包格式与兼容范围

采用 `SKILL.md` 的 YAML frontmatter 加 Markdown 正文；必需 `name` 与 `description`，正文非空。平台 ID、版本号、所有者、文件哈希由后端生成，不要求用户额外写入已有包。

```text
skill-root/
  SKILL.md
  references/
  scripts/
  assets/
```

允许其他合法相对目录，不强制资源只位于上述三个目录。保留全部合法文件及目录层级、二进制内容和未知元数据字段。`license`、`compatibility`、`metadata` 等字段用于展示；`allowed-tools` 只可作为需求声明，不能授予权限。

支持单文件 `.md`、`.zip`、目录文件列表上传；单文件按 `SKILL.md` 存储。ZIP/目录只允许一个 Skill 根，可有一层包装目录；存在多个 `SKILL.md` 时明确拒绝并要求分别导入，不能擅自挑选最浅文件。

### 5.2 管理界面与生命周期

- Skill 库展示名称、描述、启用状态、当前版本、包大小、文件数量及运行环境兼容性。
- 上传完成后展示校验结果、完整文件树、正文预览、脚本清单及依赖要求；初始停用，由作者启用后进入发现目录。
- 用户可上传新版、查看版本详情、导出指定版本、将旧版设置为当前版本。版本切换不修改旧包。
- 名称作为发现标签，内部访问使用 ID；同一作者启用库内的发现名称必须唯一。重名导入提示改名或选择更新已有 Skill，不覆盖既有包。
- 在线修改正文或文本参考文件必须生成新版本，保留未修改资产；不得在原版本目录原地编辑。
- 停用或逻辑删除从后续目录移除，并撤销后续文件读取和执行资格；历史记录和被引用版本仍保留。不能删除时显示引用原因。
- Skill 描述存在但脚本环境不支持时，显示“可读取，部分执行不可用”，不能显示完整可运行。

### 5.3 默认上传边界

以下为首版工程默认值，可配置但必须通过能力接口公布并在测试环境固定；不是性能实测结论。

| 项目 | 默认上限 |
| --- | --- |
| 单次上传原始数据 | 20 MiB |
| 解压后总大小／单文件大小 | 100 MiB／20 MiB |
| 包内文件数量／目录深度 | 500／16 层 |
| `SKILL.md` 大小 | 64 KiB UTF-8 |
| name／description | 64／1,024 个 Unicode 码点 |
| 单作者启用 Skill 数量 | 50 |
| 单作者全部版本及产物存储配额 | 1 GiB，按实际持久化字节统计 |

校验绝对路径、`..`、Windows 盘符、反斜杠变体、NUL、规范化后重复路径、符号/硬链接及特殊文件。拒绝加密 ZIP 和解压膨胀；限额在流式接收与实际解压时执行，不仅相信压缩包头。文本编码错误明确报告，不能替换字符后冒充原始内容；二进制按原字节保存。

## 6. 任意轮次发现与渐进加载

### 6.1 发现规则（2026-10-12 更新：用户引用与自动发现）

- 每个 Run 都生成当前作者启用且可访问的摘要目录，包括 ID、名称、描述、版本 ID、读取位置及兼容性。目录在 Run 内固定；库变更在下一 Run 生效。
- 模型在对话任意轮次，以及一次 Run 的后续模型请求中，都可根据任务与新信息判断是否需要 Skill。
- 用户显式引用的 Skill 必须通过 `read_skill` 读取，并在执行相关工作前进入后续模型请求；初始请求只提供摘要与引用。加载失败明确失败，不忽略用户指定后正常回答。
- 用户未指定时，模型按描述匹配并调用 `read_skill`；没有适用项时正常处理，无需强制使用 Skill。
- 首版最多 50 个启用项，以完整摘要目录实现发现，不引入向量检索或独立路由模型。达到限额时禁止继续启用并给出管理入口，不偷偷裁剪目录。
- 小说正文、设定、参考文件或脚本输出中的命令不构成用户选择或权限变更。元数据按数据安全编码，不插入未经转义的系统标签。

### 6.2 引用、版本与可见状态

Skill 管理集中于全局“设置 → Skill”；写作助手输入区通过引用按钮或 `$` 搜索将技能插入消息，名称含空格或标点时使用 `$[名称]`。不提供独立的本轮选择、版本选择、对话固定或发现开关。

| 来源 | 生效范围 | 版本规则 |
| --- | --- | --- |
| 消息中的用户显式引用 | 该消息提出的任务；相关追问依据上下文继续使用，不成为永久配置 | 提交稳定 skill ID；受理时由服务端锁定当前版本 |
| 模型按任务自动发现 | 当前任务及相关历史 | 读取本 Run 目录固定的版本 |

用户引用与自动发现同时可用；所有已启用 Skill 始终可发现。两种触发均渐进读取完整指导、参考文件和脚本。显式引用不可用时拒绝受理；未消费指导不得执行依赖工作或发布成功回答。Skill 启停控制单项是否可用。

新版本不改变正在执行的 Run；新任务目录使用当前版本。重试显式引用保留原任务版本，历史仍标注原版本。一个 Run 对同一 Skill 只使用一个版本。

界面与记录区分“可发现”“已加载”“已进入模型请求”“脚本已执行”。持久化完成但尚未送入请求不能显示模型已读取；所有这些状态均不能宣称模型严格遵循了全部指导。

### 6.3 工具契约

| 工具 | 模型参数 | 必须返回或校验 |
| --- | --- | --- |
| `read_skill` | skillId | 固定版本、完整正文、根位置、资源清单、执行兼容性 |
| `read_skill_file` | skillId、relativePath；可选已公布的分页参数 | 同版文件、MIME、哈希、内容或明确分页信息 |
| `run_skill_script` | skillId、relativePath、arguments 数组、可选 inputs 列表 | 执行 ID、环境、退出码、stdout/stderr、产物或结构化错误 |

服务端注入作者、作品、对话、Run 和固定版本；模型不能传宿主机路径、所有者或任意环境变量。脚本入口必须属于已加载包的合法脚本文件，不能以字符串拼接方式交给宿主机 Shell。结果沿用 `{success, data, error, budget}`。

`inputs` 使用安全文件名及结构化来源：本轮已读取章节/设定的固定内容、当前对话可访问的未过期 artifact ID，或最多 64 KiB 的 UTF-8 文本。后端校验引用、保存实际输入与哈希，将其物化到执行目录的 `input/`，公布包根、输入目录、输出目录的沙箱内路径。文本来源明确记录为模型生成，不冒充作品原文；脚本读取文件不等于该正文已进入模型请求。前一脚本产物只有保存并取得 artifact ID 后才能作为后续执行输入，不跨 Run 共享任意可写目录。

重复加载不重复追加完整正文；正文已不在有效上下文时允许重新注入。读取超限时返回显式错误或带完整分页标记的结果，不能把截断内容称为全文。

同一模型响应中的工具按顺序执行，但参数已提前生成；依赖 Skill 正文的操作必须在后续模型请求生成。同批“加载指导并执行脚本”不得被记录为已经依据新指导完成规划。

文本参考文件支持分页读取；二进制资源提供文件元数据与受权限保护的下载引用，可交给脚本处理。本期不承诺模型直接理解图片/PDF，也不将下载链接当作已读证据；模型需要正文时通过受支持脚本提取。后续多模态输入需另行扩展适配器和验收。

## 7. 脚本执行与生成文件

### 7.1 执行环境

新增独立 `SkillExecutor`。Java 服务负责受理、授权、预算与记录，执行器运行上传脚本，不依赖 OpenFic Python 服务。

- 首版提供 Python 3 与 Node.js 两类受控环境，以镜像摘要固定版本，公布解释器与预置依赖清单。Java 主服务无需安装这些运行时。
- 上传不会运行代码或自动安装依赖。Skill 可声明依赖要求；缺失解释器/依赖返回 `SKILL_RUNTIME_UNAVAILABLE` 或 `SKILL_DEPENDENCY_UNAVAILABLE`。
- 首版无外网、无动态依赖安装。不能由 Skill 的文本请求改变该策略；更多环境可通过运营配置预置后公布。
- 非特权执行，包只读，每次脚本调用有独立可写目录；只传入本次明确选择的输入文件，不暴露整个宿主机、作品目录或其他 Run 文件。
- 不提供数据库、模型密钥、Java 服务环境变量、Docker socket 或宿主机挂载。执行服务不以用户可控参数启动特权容器。
- 脚本无法直接调用正文写接口；生成正文作为产物，只有合法章节修改任务才可再通过 `propose_edit` 形成候选稿。

Docker 文件卷用于持久化；运行隔离还须由受限执行容器/沙箱实现，两者不能混同。执行器失效时章节和 Skill 管理仍可使用，执行调用返回明确不可用错误。

### 7.2 默认执行限额与终态

单脚本默认最多 30 秒、1 CPU、512 MiB 内存、64 个进程；stdout 与 stderr 合计最多 256 KiB；单次产物最多 20 个、合计 20 MiB，并计入作者存储配额。所有限制取本轮剩余预算与独立限额的较小值。

输出超过上限终止执行并返回 `SCRIPT_OUTPUT_LIMIT_EXCEEDED`，保留带截断标记的诊断；非零退出码为 `SCRIPT_FAILED`；超时、取消分别记录。单脚本错误可回填让模型调整，不代表整个 Run 必然失败；后端不得自动重跑上传脚本。

Run 取消、超时或服务失联必须终止执行进程树。启动恢复时检查遗留执行实例并停止；晚到结果不得推进已终态 Run。数据库记录 `STARTED` 不能被解释为脚本完成。

### 7.3 文件交付

- 产物按执行 ID 隔离，保存规范化路径、大小、哈希、MIME 与所属 Run，校验不是链接或越界文件后才发布。
- 作者可预览受支持的文本、下载其他格式；不直接以可执行 HTML/SVG 在产品同源页面打开上传或生成内容。
- 成功任务的合法产物作为本轮附件显示；失败/取消任务的合法已保存产物仅在执行详情中标为“未完成任务产物”，不冒充最终交付。
- 下载按所属作者和作品校验，通过产物 ID 访问，不暴露服务端绝对路径或无权限的静态目录。
- 产物默认保留 30 天，详情显示到期时间。到期清理保留元数据并显示“文件已过期”；被固定输入或保留操作引用的文件暂不清理。

## 8. 存储、版本发布与备份

### 8.1 存储决策

当前 PG 自身运行在 Docker 数据卷上。本文比较的是“把包内容存成 PG 数据”与“保存为普通文件”，选择 **PG 管理业务状态和模型输入，文件卷保存完整不可变包及产物**。

| 存储 | 权威数据与用途 |
| --- | --- |
| PG | 对话、轮次、执行记录、压缩摘要、选择偏好、版本引用、文件清单、实际模型输入及执行状态 |
| 文件存储 | 完整版本包原始字节、上传暂存、执行工作目录和生成产物 |
| PG 解析索引 | 名称、描述、兼容性、可选文本检索索引；由版本包派生，不独立编辑 |

不可变版本包是 Skill 文件内容权威来源；PG 中实际发送文本是该次调用依据。所有文件访问校验版本及文件哈希。解析元数据修改也须发布新包版本。

不把所有二进制塞进 PG，避免扩大数据库/WAL和执行时反复物化；不只保存文件目录，避免失去权限、版本引用和输入追踪。通过 `SkillStorage` 接口隔离存储位置，未来可替换为对象存储；本期不增加对象存储依赖或多实例运行承诺。

### 8.2 文件布局与发布

```text
<data-root>/skills/staging/<upload-id>/
<data-root>/skills/packages/<version-id>/
<data-root>/workspaces/<conversation-id>/<run-id>/<execution-id>/
<data-root>/artifacts/<artifact-id>/
```

路径由服务端 ID 构造，不能使用未校验用户名称作为宿主机路径。临时执行目录不作为长期包存储。

发布流程：预留上传配额与 ID → 写 staging 并校验 → 计算规范化路径、内容哈希和总清单 → 持久化文件并在同一文件系统原子移动到版本目录 → PG 事务写版本/清单并标记 `READY`。文件和父目录持久化完成后才能标记 READY。

上传状态至少为 `UPLOADING / VALIDATING / READY / FAILED`；只有 READY 可启用。文件系统发布和 PG 提交不宣称是一个事务。PG 提交失败留下的孤立目录由恢复检查及 GC 清理；提交结果未知先回读版本状态，不盲目删除可能已被引用的目录。READY 包丢失/损坏返回 `SKILL_PACKAGE_UNAVAILABLE`，不得从别的版本替代。

### 8.3 清理与恢复

- 失败 staging 默认 24 小时后清理；活动上传、执行和未知提交状态不得清理。
- 已发布版本只在逻辑删除、没有对话/Run/产物引用且满足保留策略时物理回收。历史运行引用的版本不自动删；停用不释放历史包占用。
- 清理前在 PG 登记并复查引用，失败可重试；原始消息、摘要和执行元数据本期不自动清理。
- 重启检查 READY 路径、未完成上传与遗留执行；不完整版本不可进入发现目录。
- 默认根路径由 `MOJIE_DATA_DIR` 配置。本地 Java 使用宿主机目录；生产 Compose 新增持久化卷。初始化主服务 UID `10001` 的写权限，并为执行器提供只读版本挂载和独立工作目录。

### 8.4 备份与恢复验收

备份包含 PG 和完整版本包、仍有效产物，不要求备份可重新生成的执行暂存。备份窗口暂停新上传、版本发布和物理清理，待文件相关提交完成后固定 manifest，协调数据库与文件备份；活动脚本先结束或停止，避免半份产物。

恢复到独立环境后按版本清单校验路径、大小和哈希，核对对话与 Run 引用；恢复活动任务为明确失败，不续跑。验证旧对话能继续、指定旧版本能读取、产物可下载以及模型输入可追溯。仅容器重建后文件还在不算备份验收。

## 9. 数据模型与事务要求

### 9.1 新增与扩展实体

下表定义职责与关键约束，最终 DDL 由工程设计承接，不要求逐字段照抄。

| 实体 | 关键字段、关系与约束 |
| --- | --- |
| `tb_conversation` | owner、project、title、status、last_seq、active_run、固定模型/接口配置；不可跨作品引用 |
| `tb_conversation_message` | conversation、seq、角色、原始用户文本及 skill_mentions 或助手来源引用、轮次状态；`UNIQUE(conversation, seq)`；产品展示层，不用于反向生成协议 |
| `tb_conversation_compaction` | conversation、覆盖消息边界、摘要正文、父摘要、模型配置、input_snapshot；不可覆盖原始消息 |
| `tb_skill` | owner、发现名称、enabled、current_version、deleted_at；同作者启用发现名称唯一 |
| `tb_skill_version` | skill、version_id、包哈希、存储键、状态、解析元数据、大小、运行兼容性；READY 内容不可变 |
| `tb_skill_file` | version、规范化 relative_path、hash、size、MIME；`UNIQUE(version, relative_path)` |
| `tb_agent_input_snapshot` | 内容哈希、完整逻辑请求、来源引用及摘要/Skill 版本；密钥不入库 |
| `tb_run_skill` | run、skill、version、选择来源、加载消息/工具执行引用；`UNIQUE(run, skill)` |
| `tb_skill_execution` | run、tool_execution、version、脚本、参数、输入文件来源与哈希、环境摘要、状态、退出码、输出与执行句柄；不得脱离真实工具步骤 |
| `tb_artifact` | owner、project、run、execution、存储键、hash、size、MIME、expires_at、状态 |
| `tb_agent_run` 扩展 | conversation、触发消息、重试来源、输入边界、task_type、可空章节、预算配置；章节类型保留版本完整性约束 |
| `tb_agent_message` 扩展 | 保留 Run 内序号、角色和原始协议；关联 conversation 和展示消息；历史输入以消息 ID 引用，不受当前 run_id 限制 |
| `tb_agent_model_call` 扩展 | 有序 input_message_ids、input_snapshot 引用、阶段、输入估算；校验引用全部已提交且属于当前对话或当前合成输入 |

产品层保存原始用户输入和最终回复引用，协议层保存实际提供给模型的消息；两者用途不同，不在每个 Run 再复制一遍全部历史。新增模型输入快照是审计依据，不是第二套可修改聊天历史。

### 9.2 核心事务边界

| 边界 | 必须原子完成 |
| --- | --- |
| 发送新消息 | 幂等校验、作品/对话活动槽与序号校验、产品输入、Run、初始协议消息、选择/目录版本引用、queued 事件 |
| 重试 | 引用原输入、固定历史边界、创建新 Run 和新预算、活动槽；不插入重复用户消息 |
| 请求模型 | 校验输入引用、提交完整快照/调用开始、预算和事件；网络请求在事务外 |
| 工具回填 | 工具步骤、实际消息、Skill/证据引用、预算和事件；执行文件发布通过状态机协调 |
| 压缩 | 摘要及覆盖边界、输入来源、阶段结果；提交后可用于模型请求 |
| Run 成功 | 唯一终态、最终回复引用、可选建议、终态事件、对话和作品槽释放 |
| Run 失败/取消 | 唯一终态、未完成展示状态、开放记录收尾、槽释放；不发布章节候选 |
| 建议采纳 | 沿用目标版本校验、正式正文、一次历史写入及建议状态事务 |

锁顺序统一为作品 → 对话 → Run／建议 → 章节，Skill 版本只读；管理写入和配额预留需有单独固定顺序。模型与脚本运行不持有长数据库事务。

## 10. 接口、事件与错误

### 10.1 接口需求

| 接口 | 行为 |
| --- | --- |
| `POST /api/v1/projects/{id}/conversations` | 新建，返回独立 conversation ID |
| `GET /api/v1/projects/{id}/conversations` | 统一历史分页列表，按创建时间倒序 |
| `GET/PATCH /api/v1/conversations/{id}` | 详情、重命名；变更使用乐观版本 |
| `GET /api/v1/conversations/{id}/messages` | 按 seq 分页查询可展示轮次及 Run 引用 |
| `POST /api/v1/conversations/{id}/messages` | 受理输入，202 返回 message ID、conversation seq、run ID |
| `POST /api/v1/conversations/{id}/messages/{messageId}/retry` | 重试已失败/取消轮次；仅允许该轮仍为最新用户输入，无后续轮次 |
| `POST /api/v1/skills/import` | multipart 文件/目录；返回 upload ID 与校验状态，不把接收等同 READY |
| `GET /api/v1/skill-uploads/{id}` | 查询校验、错误和新版本引用 |
| `GET /api/v1/skills`、`GET/PATCH/DELETE /api/v1/skills/{id}` | 分页库、详情、启停/当前版本、逻辑删除 |
| `POST/GET /api/v1/skills/{id}/versions` | 上传/文本编辑生成新版本、分页版本历史 |
| `GET /api/v1/skills/{id}/versions/{versionId}` | 完整清单与兼容性 |
| `GET /api/v1/skills/{id}/versions/{versionId}/export` | 导出可重新导入的完整 ZIP |
| `GET /api/v1/skills/{id}/versions/{versionId}/files/{fileId}` | 受保护预览/下载，通过 file ID 定位合法相对路径 |
| `GET /api/v1/artifacts/{id}`、`GET /api/v1/artifacts/{id}/download` | 产物状态与下载；过期状态可查 |

消息发送至少包含 `content`、`clientRequestId`、`expectedConversationSeq`、`taskType`、可选 `targetChapterId/expectedVersion`、`skillMentions: [{skillId, name}]`。owner 从服务端身份获取，不能由 body 指定；本期保留单作者部署，公开写入口仍须有受保护访问入口。

复用 Run 查询、取消、SSE 与建议接受/拒绝接口，详情增加对话、任务类型、实际预算、Skill 和产物信息。新增分页接口遵循现有 opaque cursor 与默认 20/最大 50 的约定；聊天显示顺序始终由 seq 决定。

### 10.2 事件与展示恢复

保留 run/model/tool 事件；增加 `context.compacted`、`skill.loaded`、`script.started`、`script.finished`、`artifact.created`。新增事件同样在相关记录提交后发出并持久化，不能由前端推测。

SSE 仍按 Run 跟踪，不要求新增 WebSocket。对话页先获取消息和活动 Run 快照，再按 lastEventSeq 订阅；runId + seq 去重，旧对话请求与迟到快照不得覆盖当前对话。上传进度使用状态查询，不混入 Run 事件序列。

### 10.3 主要错误

沿用模型、预算、取消、版本、容量和幂等错误；补充 `CONVERSATION_VERSION_CONFLICT`、`CONVERSATION_MODEL_UNAVAILABLE`、`SKILL_INVALID_PACKAGE`、`SKILL_UPLOAD_LIMIT_EXCEEDED`、`SKILL_QUOTA_EXCEEDED`、`SKILL_VERSION_CONFLICT`、`SKILL_UNAVAILABLE`、`SKILL_PACKAGE_UNAVAILABLE`、`SKILL_RUNTIME_UNAVAILABLE`、`SKILL_DEPENDENCY_UNAVAILABLE`、`SKILL_EXECUTOR_UNAVAILABLE`、`SCRIPT_FAILED`、`SCRIPT_TIMEOUT`、`SCRIPT_OUTPUT_LIMIT_EXCEEDED`、`CONTEXT_COMPACTION_FAILED`、`CONTEXT_TOO_LARGE`、`ARTIFACT_EXPIRED`。

越权和不可访问资源不返回内容或宿主机路径。工具错误携带可读说明和 retryableByModel；该标记不触发执行层自动重试。具体 HTTP 状态映射在 OpenAPI 中固定。

## 11. 预算、可观测性与运行边界

新增对话任务采用以下默认配置；旧接口兼容任务保持旧默认，除非明确版本升级。

| 项目 | 新对话任务默认值 |
| --- | --- |
| 最大模型请求／工具调用 | 16／32，包含压缩请求与 Skill/脚本工具 |
| 累计新增工具文本 | 120,000 Unicode 码点；错误和重复返回计入 |
| 最大应用上下文 | 200,000 码点；同时遵守配置的提供方窗口与预检 |
| 单次模型请求／Run 运行超时 | 60／300 秒，取剩余时间较小值 |
| 排队超时 | 60 秒 |
| 最大输出 allowance | 16,000 tokens，实际由支持模型及配置固定 |
| 单 Run 不同 Skill 加载数 | 8，包含用户引用和助手发现 |
| 单条聊天输入 | 8,000 Unicode 码点 |

预检拒绝显式引用超过加载上限，不先受理再默默忽略。历史重发不重复累计新增工具文本；实际请求仍计入完整上下文。通过工具渐进读取的指导也计入上下文，文件存储配额和脚本限额另行计量。

模型仍需预留最终响应；工具声明没有后续模型额度时整批拒绝。所有限额存入 Run 配置快照，数据库不再使用仅适用于旧 8/12 次预算的全局硬编码约束；调用索引、SQL条件、能力接口、提示词和 UI 必须同步。

记录 Run/对话标识、版本、模型用量、压缩前后估算、脚本耗时/退出码、包存储和配额；普通页面不显示隐藏推理、系统全文、密钥或堆栈。这些默认值须用真实材料验证后评估，不能作为稳定完成或延迟承诺。

## 12. 验收与交付阶段

### 12.1 确定性、集成与端到端验收

| 编号 | 场景 | 必须满足 |
| --- | --- | --- |
| CS-AC-01 | 新建两对话并轮流发送 | 历史、摘要、消息引用、工作目录隔离，个人库仍可发现 |
| CS-AC-02 | 同对话三轮追问 | 后续请求含正确已提交历史；能引用上一轮结论 |
| CS-AC-03 | 多标签页重复发送/旧序号发送 | 幂等无重复消息；旧边界冲突；仅一个活动 Run |
| CS-AC-04 | 切换章节/对话、刷新、断线与迟到快照 | 活动 Run 不取消，展示恢复且无串对话 |
| CS-AC-05 | 普通聊天无目标章；章节类型缺目标 | 前者可完成，后者受理前拒绝；权限按类型执行 |
| CS-AC-06 | 上轮读章、作者保存/采纳后下一轮修改 | 新轮重新固定并完整读当前基准；旧证据版本明确 |
| CS-AC-07 | 失败/取消留下未配对工具调用，再继续 | 下一请求无非法协议；原记录仍可追踪 |
| CS-AC-08 | 重试失败轮次，及有后续轮次时重试 | 前者新 Run 不重复用户输入；后者拒绝隐式分支 |
| CS-AC-09 | 原模型配置不可用或切换接口 | 旧对话明确不可用，不混用协议；新对话可选当前配置 |
| CS-AC-10 | 长对话跨压缩阈值 | 完整记录保留，摘要覆盖可追溯，工具组完整 |
| CS-AC-11 | 压缩失败或压缩后仍超限 | 明确错误，无静默删历史或伪造正常回答 |
| CS-AC-12 | 上传 Markdown/ZIP/目录，包含二进制与脚本 | 完整包、路径与哈希保留，导出再导入内容一致 |
| CS-AC-13 | 多根包、编码错误、重复路径、穿越、链接、解压膨胀 | 明确拒绝，无越界文件、半个 READY 版本或配额泄漏 |
| CS-AC-14 | 上传成功但停用，再启用 | 未启用不可发现；启用后下一轮进入摘要目录 |
| CS-AC-15 | 第 1 轮不匹配，第 3 轮匹配 | 模拟请求目录持续存在，模型第 3 轮可加载；不只首轮发现 |
| CS-AC-16 | 同 Run 新证据引出另一 Skill | 后续请求可加载，路径不写死 |
| CS-AC-17 | 用户引用、删除引用、无引用自动发现 | 指定项必须读取并送达；下一任务不强制继承；始终自动发现 |
| CS-AC-18 | 已加载后压缩正文，再需使用 | 按固定版本重新注入，不因加载标志跳过 |
| CS-AC-19 | 运行中上传新版、引用后改名、重试、停用、删除 | Run 固定版本；引用稳定 ID；重试保留原显式版本；不可用引用明确拒绝 |
| CS-AC-20 | 加载结果落库后取消、未发下一模型请求 | 展示已加载但未确认送达，不称模型已读或遵循 |
| CS-AC-21 | 指导/正文注入指令、越权 file ID/path | 不扩大权限、不泄漏其他作者/作品/版本文件 |
| CS-AC-22 | Python/Node 使用已读内容、文本和前次产物生成文件 | 输入来源/版本/哈希准确；使用公布环境；退出码、输出、哈希和下载对应真实执行 |
| CS-AC-23 | 依赖缺失、非零退出、超时、输出/内存/进程超限 | 分类真实，执行受限，无执行层自动重跑 |
| CS-AC-24 | 脚本读取密钥、其他目录、访问外网或修改包 | 拒绝；包只读，主服务凭据和其他工作目录不可见 |
| CS-AC-25 | 脚本运行中取消、服务中断、晚到结果 | 进程树停止，终态不回退、不发布章节候选 |
| CS-AC-26 | 产物下载、到期、伪造链接文件、危险预览 | 权限与哈希正确，过期明确，不发布越界文件或同源执行内容 |
| CS-AC-27 | 文件发布后 PG 失败/提交未知、缺包与重启 | READY 语义正确；恢复先回读；孤立目录可清理且不误删已引用包 |
| CS-AC-28 | 空库迁移、旧任务迁移、输入链路查询 | 旧记录保留；新引用同对话且已提交；实际快照可还原 |
| CS-AC-29 | 数据库中断、终态竞争及建议采纳 | 无部分消息/建议提交，活动槽正确，版本冲突不覆盖正文 |
| CS-AC-30 | 新预算与旧兼容预算分别跑边界 | DB/循环/提示/能力/UI一致，无硬编码导致提前失败 |
| CS-AC-31 | 完整备份后在独立环境恢复 | 对话可继续，旧版包和有效产物可用，遗留任务明确失败 |
| CS-AC-32 | 配额并发预留、失败上传和 GC | 不超配额、不重复释放、不清理活动或历史引用文件 |

模拟模型验证协议与路径能力，不代替真实模型会主动选对 Skill 的质量验收。数据库、文件发布、沙箱和恢复均需真实组件验证，不能只用 mock 验证核心边界。

### 12.2 真实模型评估

固定材料覆盖：连续三轮后首次匹配、明确选择、无匹配、两 Skill 相似描述、同 Run 二次发现、压缩后续聊、脚本报告、依赖不可用及章节修改采纳。逐次记录选用版本、实际输入、预算、耗时、完成原因和产物，失败样本同样保留。

技术验收要求至少一个实际配置模型完成连续聊天、后续轮次发现、正文/参考渐进读取、脚本产物以及完整章节建议采纳闭环。人工逐例核查选用是否合适、指导是否产生有效结果、来源/版本是否真实、未覆盖范围是否诚实。不以固定工具顺序或加载次数代替效果判断。

### 12.3 开发与签收顺序

1. **契约与迁移：** 任务类型、对话/输入引用、Skill 版本与文件存储状态机、预算和错误契约；同步 ADR/OpenAPI。
2. **对话闭环：** 新建/切换、连续历史、发送幂等、失败协议处理、旧任务迁移、SSE恢复和压缩。
3. **完整包与发现：** 上传/校验/启停/导出、不可变版本、每轮摘要、显式/自动加载和送达记录。
4. **执行与产物：** Python/Node 环境、资源与权限限制、取消恢复、产物下载和配额。
5. **整体验收：** CS-AC、章节回归、真实模型质量、备份恢复；记录失败与未签收项。

对话、上传、脚本运行可分别做内部阶段签收；第 2.1 节完整范围与第 12 节发布门槛全部通过前不得标记本功能完整交付。

## 13. 兼容、文档替代与交付物

### 13.1 旧入口及历史迁移

- 新对话入口使用 Conversation API；旧 `POST /agent/runs` 保留兼容，按一次独立章节修改任务受理，不自动续接前一个 Run，不默认发现个人 Skill。
- 旧入口仍支持原先“只分析或给建议”的行为及 8/12 次预算；新入口显式区分任务类型，不能用类型拆分破坏旧调用者。
- 旧历史 Run 可按一条 Run 一个独立对话迁移，标明历史来源并保留旧 ID、事件、建议、实际预算和输入引用；无须重算旧模型调用或改写原消息。
- 旧表新增字段允许兼容历史数据；新任务用类型条件约束目标章/版本。迁移不伪造旧任务曾使用 Skill 或连续上下文。

### 13.2 对既有 PRD 的替代范围

| 旧要求 | 新功能口径 |
| --- | --- |
| 每 Run 不继承历史 | 同 Conversation 连续；新建 Conversation 独立；旧入口仍独立 |
| 每任务必有目标章 | 新 `CHAT` 允许无目标；章节任务保留完整证据条件 |
| 不引入历史压缩或文件/脚本工具 | 本功能明确新增受追踪压缩、Skill文件访问与隔离执行 |
| 固定七工具与 8/12 次预算 | 新 Run 按类型/能力提供工具及预算快照；旧接口兼容不变 |
| 原单作品活动槽与全局容量 | 本期保留，并新增对话序号与活动 Run 约束 |
| AI 不直接改正文、成功后发布建议、作者确认采纳 | 继续有效，Skill/脚本也不得绕过 |

本文只替代新功能涉及的边界，不宣称旧 MVP 验收已完成。工程实施需更新 `README.md` 文档入口、ADR、Framework Design、HTTP/SSE 与 OpenAPI、部署配置和验证记录；本次 PRD 编制不修改当前接口或运行配置。

### 13.3 工程参考与交付物

OpenFic 固定基线可借鉴 `context/build_context.py` 的历史/静态上下文分层、`context/parts/skills.py` 的摘要发现以及 `tools/impls/skill/skill.py` 的激活/参考读取。其 `skill_import_service.py` 主要提取正文和 Markdown 参考资料，不能直接等同完整脚本/资产包；路径与解压安全、不可变版本和本项目事务需自行实现验证。
