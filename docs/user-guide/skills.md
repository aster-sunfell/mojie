# 如何创建 Skill

Skill 为墨界助手按需提供角色、写作方法和参考资料。适合人物一致性审稿、叙事节奏分析、文风约定等任务。助手加载指导后，结合当前作品的系统工具完成工作。

## 创建与使用

1. 创建 UTF-8 编码的 `SKILL.md`，填写名称、适用场景和指导正文。也可以直接导入单个 Markdown 文件，平台会将其作为 `SKILL.md`。
2. 在“设置 → Skill → 添加 Skill”中导入，预览说明后启用。技能库由所有作品共用，读取作品内容时仍限定当前作品。
3. 描述应写清“什么时候使用”，正文写清角色、步骤、输出格式和证据不足时的处理方式。
4. 助手根据当前任务，从已启用 Skill 的名称和描述中发现相关技能，再读取指导。也可以在消息中输入 `$` 选择 Skill，或明确说出要使用的名称；助手会先读取它。

Skill 引用只针对当前消息，不会成为永久角色设置。历史对话可能保留此前内容；需要独立角色或任务上下文时请新建对话。每轮固定技能版本，上传或编辑新版不会替换历史轮次使用的版本。每轮最多加载 8 个 Skill。

## 可用的系统能力

这些工具由系统提供，实际调用者是助手。可以在指导中写出工具名称和使用顺序，无需编写代码，也不需要声明工具权限。

| 能力 | 工具 | 使用说明 |
| --- | --- | --- |
| 查看作品名称和标识 | `read_project` | 读取当前作品已保存的信息 |
| 浏览、读取和搜索章节 | `list_chapters`、`read_chapter`、`search_chapters` | 先定位相关章节，再按需读取；搜索为文字匹配 |
| 浏览、读取和搜索设定 | `list_settings`、`read_settings`、`search_settings` | 可查人物、世界观和写作规则 |
| 加载技能和参考文本 | `read_skill`、`read_skill_file` | 读取本轮固定版本的指导和包内文本资料 |
| 提出章节或设定草稿 | `propose_chapter_edit`、`propose_setting_edit` | 仅在用户要求创作或修改时使用；生成候选稿，由作者审阅并保存 |

章节 ID、设定 ID 和版本应来自本轮实际读取的工具结果，不要写死在 Skill 中。更新已有内容前，助手必须在本轮完整读取目标内容。用户只要求分析时，Skill 不能额外要求创建或修改正文、设定。

工具只读取当前作品的已保存内容，未保存的编辑器草稿不会自动提供给助手。当前选中的参考章节是线索，用户明确指定的章节优先。不要要求默认读取整部作品；先搜索和定位，仅在整章审阅或修改时读取完整目标章。

## 参考资料与导入格式

简单 Skill 只需一个 `SKILL.md`。需要更多资料时，可以导入 ZIP 或目录：

```text
character-review/
  SKILL.md
  references/
    review-checklist.md
```

在指导正文中写“需要时读取 `references/review-checklist.md`”，助手会按需使用 `read_skill_file`。导入支持一层外包装目录，包内只能有一个 `SKILL.md`。文本内容需要 UTF-8；二进制文件可保存和下载，不能作为已读取文本的证据。

单次上传最多 20 MiB，解包后最多 100 MiB、500 个文件或目录条目，单文件最多 20 MiB；`SKILL.md` 最多 64 KiB。实际导入限制也可在 Skill 库底部查看。

## 不支持的能力

- 不执行 Python、JavaScript、Shell 或其他脚本，不安装依赖。
- 不浏览外部网页，不调用第三方 API、MCP 或其他平台的专属工具。
- 不读取任意本地文件、环境变量、数据库，也不能跨作品读取内容。
- 不注册新工具、扩大权限或直接覆盖正式正文、设定。`allowed-tools` 等元数据只是包的声明，不能授予权限。

其他平台的 Skill 可以导入，但依赖脚本、联网或专属工具的部分无法使用。包内文件会完整保留，脚本可预览和导出，但不会执行或作为技能参考上下文加载。导入提示只能识别部分文件和元数据声明，请预览指导，删除或改写不适用步骤；“导入成功”表示包已保存，不代表全部要求均受支持。

## 可复制的示例

将以下内容保存为 `SKILL.md`，修改名称、描述和正文后即可导入。

```markdown
---
name: 人物一致性审稿
description: 当用户要求检查人物行为、动机或对白是否符合已有人物设定时使用。
---

# 人物一致性审稿

你是一位关注人物动机和行为连贯性的小说编辑。依据作品中实际读取到的内容分析，不补写不存在的设定。

## 工作步骤

1. 根据用户要求定位目标人物和章节；指代不清时先澄清。
2. 使用 list_settings、search_settings 定位相关人物设定，再用 read_settings 读取。
3. 使用 list_chapters、search_chapters 定位相关情节，用 read_chapter 读取必要章节。整章审稿时完整读取目标章，不默认读取整部作品。
4. 比较行为、对白和动机，区分明确矛盾、合理变化和证据不足。
5. 仅当用户明确要求修改时，基于本轮完整读取的内容提出候选稿，交由作者审阅保存。

## 输出要求

- 先给出主要判断，再列出问题及依据。
- 写清相关章节、设定和具体内容，提供可操作的改进建议。
- 没有足够证据时明确说明，不能把推测写成作品事实。
- 仅要求分析时，输出分析和建议即可。
```
