# 统一写作助手设计方案

日期：2026-10-12。状态：已实现统一前端入口和按需上下文；工作区支持并排阅读、专注章节和专注对话，已移除上下分屏。新轮次不再选择任务模式。

## 1. 布局与入口

工作区保留左侧章节导航，顶部提供“专注章节 / 并排阅读 / 专注对话”阅读布局切换。宽屏选中章节后默认并排阅读：正文位于中间，完整写作助手位于右侧。标题、消息记录和输入框属于同一栏，输入框始终位于该栏底部。阅读布局只控制显示，不改变助手任务或发送协议。

取消“章节任务 / 连续对话”两个 tab，统一名称为“写作助手”。采用现有持久化 Conversation 能力。远程和本地均无旧任务，本次不建设旧任务入口或迁移流程。

桌面左侧导航宽 220px，并排助手宽 380–480px。专注章节收起整个助手，正文阅读宽度上限 760px；专注对话收起正文，消息与输入框在同一居中区域内，宽度上限 760px。未选中章节时直接显示专注对话，避免空正文占位。沿用浅色背景、墨绿色操作色和正文衬线字体。

## 2. 助手的结构

从上到下为：

1. 助手标题区：写作助手、当前对话标题、运行状态、历史对话和新建。移除重复的“对话消息”工具栏。
2. 消息区：用户输入、助手最终回复、修改建议入口、来源与附件。连续消息按时间排列。
3. 输入框：默认单行，随输入增长，最高 120px。
4. 输入工具行：Skill、可选优先参考章节、发送或停止。

历史对话在统一列表弹层中显示名称和执行状态，支持切换和重命名，不占据工作区常驻空间。Skill 选择在弹层中展示本轮选择、固定项与自动发现设置；Skill 库由同一入口进入。

## 3. 阅读布局与滚动

正文和助手均使用工具栏下的完整工作区高度。空对话也保留完整消息区，显示简短提示；发送后直接进入连续对话，不切换高度或挤压正文。

正文区与助手消息区独立滚动，输入区不跟随消息滚走。移除上下分隔线、拖拽高度、键盘调高、消息折叠及局部放大功能；通过顶部阅读布局按钮切换完整区域。

阅读布局切换不卸载正文或助手，保留各自草稿、阅读位置和后台任务。专注章节时收到新回复，在“专注对话”入口提示“有新回复”，不自动抢占正在写作的正文。

用户位于消息底部时随新内容滚动；正在阅读旧消息时保持位置，显示“查看新回复”。编辑区滚动位置不受新消息影响。

窗口宽度小于 1200px 时仅提供专注章节和专注对话，每次显示一个区域；选中章节后默认专注章节。宽屏并排布局缩窄时显示章节，用户仍可切换到对话。手机章节导航由菜单打开，软键盘弹出后工作区随可视窗口高度调整，输入框保持可见。

## 4. 对话与发送

作品没有对话时可直接输入；首次发送先自动创建持久化对话，再发送消息。创建成功但发送失败时保留对话 ID、原输入和幂等键，重试不重复创建。仅浏览页面不产生空对话。

新建按钮进入独立空白对话，首次发送再持久化；已有未发送输入按对话或新对话草稿分别保留。首次输入可生成标题。刷新后恢复最近访问的对话。所有对话统一展示，可继续发送；历史模型配置不兼容时仍需新建对话。

输入区不提供“讨论 / 审阅 / 修改”模式或“仅分析”开关。助手依据用户指令和对话历史决定查阅、分析、生成建议，允许同一轮组合完成。快捷提示只填入指令，不设置隐藏模式，不直接发送。

编辑器当前章节默认作为本轮优先参考，显示“优先参考：章节标题 · 已保存 vN”，可以移除或恢复。无参考时不显示额外说明，快捷提示仍可使用。用户明确指定其他章节时，指令优先；参考章不自动成为修改目标。具体协议见 [统一助手上下文](unified-assistant-context.md)。

Enter 发送，Shift+Enter 换行；输入法组字时 Enter 不发送。发送中防止重复提交。任务执行时按钮改为“停止”，允许准备下一轮输入但不提交；本期不增加运行中插话或排队发送。

## 5. 章节上下文与草稿

对话属于作品，切换章节继续使用当前对话。发送时固定可选参考章节 ID、已保存版本及后端正文快照，模型仅看到引用提示，按需调用 read_chapter 获取正文。未选择章节时通过 list/search 定位相关材料，再按需读取。

运行中切换编辑器章节不改变已受理的参考；历史用户消息展示当轮参考，修改建议展示实际目标。普通提问不要求读取整章；整章审核和生成修改稿应完整读取相应章节。新修改须在本轮重新读取，其工具结果必须进入后续模型请求。

未保存正文不自动保存，也不传给模型。选中参考章节且有未保存正文时明确显示“助手读取已保存版本，本轮不包含未保存正文”。当前实现生成整章候选稿；支持草稿快照和选中文本范围需要另行扩展。

## 6. 回复与修改建议

助手最终回复直接进入消息列表，不再在另一处重复显示“本次要求 / 最终分析”。执行中仅展示简短真实状态，例如“正在查阅章节”，有可展开的执行详情；中间过程不作为最终回答发布。

每条回复按需附带：

- 来源：展开查看章节、版本与对应证据。
- 修改建议：显示目标章节、修改处数、处理状态及“在正文中查看”。
- 附件：可下载文件。
- 执行详情：默认折叠，承载工具步骤、模型调用、错误细节和 Skill 实际使用情况。

点击“在正文中查看”后切换到可见正文的阅读布局，在正文显示对应差异并定位第一处待处理修改。目标不在当前章时先按现有草稿保护流程切换到目标章，不在错误章节套用建议。用户可以逐条应用、忽略或编辑建议，沿用现有修改导航工具栏。

应用、忽略及标记手动处理均在一次操作中保存当前正文与对应处理状态，无需再点“保存正文”。应用前可以编辑建议文字；应用时以当前正文草稿进行定位与合并，保留并一起保存已有手动修改，不强制覆盖。多个操作依次保存，使用上一请求返回的版本；保存期间的新输入保留为未保存正文。仅在保存成功后显示“已应用／已忽略”，失败保留本地文字与处理选择并提供重试，版本冲突不覆盖服务端新正文。普通手动写作继续使用“保存正文”。历史消息中的建议入口绑定该消息的 runId / proposalId，不随着最新一轮任务改变；处理完成后同步卡片状态。

保存成功后，差异原文和状态栏在约 200ms 内淡出收起；应用后的正文淡绿高亮约 1 秒后恢复普通字体与背景，忽略只收起建议。已处理处不保留加减号、状态栏或额外块间距，未处理与保存失败处继续审阅。批量操作同步转场，只显示一次简短反馈。保留同一个正文输入框及光标，收起期间维护当前阅读位置，不自动跳到下一处；作者主动滚动时立即停止位置补偿。支持系统“减少动态效果”，直接切换正文并通过文字反馈完成。刷新或重新打开已处理建议直接显示普通正文，不重播动画。

“查看修改记录”单独打开本份建议已保存的只读前后对照与处理版本，包括已忽略建议；记录展示生成建议时的基准原文和已保存的建议文字，完整章节以章节历史及当前正文为准。关闭记录回到正文，不重新进入差异状态。

作品工具栏常驻“待处理建议”入口，在专注章节、并排、专注对话和手机布局中均可访问，汇总全作品成功发布且仍为 PENDING、PARTIALLY_APPLIED 或 CONFLICTED 的建议，计数单位为“份”。点击打开按章节／设定目标分组的分页列表，展示来源对话、时间、剩余修改处数和处理状态，可筛选待处理与需核对。列表从作品级接口读取，统计覆盖全部历史对话，不依赖前端已加载的对话或任务页。列表内直接“审阅”复用既有草稿保护与目标定位；“查看对话”切换到来源对话并定位对应回复，保留原对话输入草稿。

阅读建议、打开列表和查看来源不清除计数；成功保存处理决定后才重新查询汇总。初次进入只展示数量，不自动弹窗；停留期间新增建议给一次短提示。汇总在任务状态变化、处理成功、窗口恢复焦点和可见页面定时轮询时刷新；读取失败显示未知状态而非零。历史对话行和作品首页卡片同时展示待处理／需核对数量。删除被占用时提供“查看待处理建议”的直接入口；该显式入口可打开列表，关闭后清理一次性的 URL 参数。

新增 GET /projects/{id}/edit-proposals/summary 和分页 GET /projects/{id}/edit-proposals，游标绑定作品及筛选条件；分页响应只包含审阅摘要，不返回整章候选稿。V16 仅新增建议队列与对话运行关联索引，不修改原内容或建议状态。

切换对话、查看其他回复和切换阅读布局不自动切换当前正文审阅对象。切换审阅对象前保留或处理未保存的建议调整；普通聊天回复不清空当前审阅。新的修改建议生成后提供查看入口，不自动替换正在处理的差异。未处理建议不阻止继续发送消息或生成新候选稿；打开、切换建议时沿用草稿与建议调整保护。

## 7. 运行状态

| 状态 | 展示与操作 |
| --- | --- |
| 空对话 | 简短说明助手按需查阅、分析或提出建议；可直接输入 |
| 发送中 | 发送按钮显示提交状态；保护输入直到受理成功 |
| 执行中 | 简短状态与停止按钮；可编辑下一轮草稿 |
| 连接中断 | 提示正在重连并查询状态；不把网络中断当成任务失败 |
| 成功 | 最终回复、来源、建议或附件进入当前轮次 |
| 失败 / 停止 | 保留本轮输入和真实状态，符合后端条件时提供重试本轮 |
| 其他对话运行中 | 提示作品有任务正在执行；允许浏览和准备输入 |
| 刷新恢复 | 恢复当前对话及真实活动任务，不重复发送 |

## 8. 前端改造范围与验收

Workspace 在章节导航外组织阅读布局：宽屏支持正文与助手并排，专注布局只显示正文或完整助手。移除旧上下分屏和 ConversationPanel 的高度计算、拖拽、折叠、放大状态；助手内容布局由可用区域决定。

对话、运行状态、输入草稿在工作区层持续存活，阅读布局只控制显示，不通过卸载组件实现。将正文审阅选择从“当前最新 run”中独立出来，显式存储选中的建议与目标章。复用现有 Conversation API、useRun、SkillLibrary、来源查看和 Proposal 审阅能力；自动创建对话和消息受理继续使用各自真实接口，不能用前端虚构对话 ID。

旧 useAgentTask 不再承担统一助手发送与历史查询职责。旧入口组件、样式和测试根据依赖检查删除；后端旧接口是否移除可另行清理，不影响本次前端方案，不建设兼容入口。

验收重点：并排模式的消息和输入框均位于右栏；专注对话的消息和输入框一起居中；正文与对话完整高度、独立滚动；切章和阅读布局切换不丢输入、阅读位置或后台任务；无章节时不保留空正文；窄屏无上下分屏；历史、Skill、幂等发送、已保存章节参考及正文审阅保护可用；手机短窗口输入和发送按钮可见。

设定建议从对话中的“在设定中查看”进入作品设定窗口，审阅后保存才生效；详见 [章节与设定修改建议](setting-edit-proposals.md)。
