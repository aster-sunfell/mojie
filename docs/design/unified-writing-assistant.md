# 统一写作助手设计方案

日期：2026-10-12。状态：已实现统一前端入口和按需上下文；新轮次不再选择任务模式。

## 1. 布局与入口

工作区由左侧章节导航和中间写作区组成。取消右侧助手栏；中间写作区纵向分为正文编辑区和下方写作助手。助手包含消息记录与输入框，输入框始终位于助手底部。

取消“章节任务 / 连续对话”两个 tab，统一名称为“写作助手”。采用现有持久化 Conversation 能力。远程和本地均无旧任务，本次不建设旧任务入口或迁移流程。

桌面端左侧导航建议宽 220px；中间占剩余空间。正文和助手内容采用相同的水平对齐，阅读宽度约 760–880px，大屏居中。沿用现有浅色背景、墨绿色操作色和正文衬线字体，取消助手中的 AGENT 大标题与重复介绍。

## 2. 下方助手的结构

从上到下为：

1. 助手标题行：写作助手、当前对话标题、对话切换、新建、收起消息。
2. 消息区：用户输入、助手最终回复、修改建议入口、来源与附件。连续消息按时间排列。
3. 输入框：多行文字输入。
4. 输入工具行：Skill、可选优先参考章节、发送或停止。

对话切换在弹层中显示名称和执行状态，重命名、归档和恢复放在该弹层中，不占据工作区常驻空间。Skill 选择在弹层中展示本轮选择、固定项与自动发现设置；Skill 库由同一入口进入。

## 3. 高度、滚动与折叠

首次进入空对话时只展示紧凑标题、简短提示和输入区，建议占 160–200px。已有对话或首次发送后展开消息区，助手建议占中间区域的 35%–40%，约 300–380px，具体随窗口高度调整。正文保留至少约 280px 可读空间；矮屏优先压缩消息区。

正文区与助手消息区独立滚动，输入区不跟随消息滚走。可以拖动正文与助手之间的分隔线，并提供键盘可操作的“扩大对话 / 恢复高度”按钮。桌面扩大对话后最多占约 60%，仍保留正文。

“收起消息”仅隐藏消息区，保留标题、状态和输入框。再次展开恢复阅读位置。任务运行中收起，标题显示“正在处理”；完成后显示“有新回复”，不自动抢占正在写作的正文。

用户位于消息底部时随新内容滚动；正在阅读旧消息时保持位置，显示“查看新回复”。编辑区滚动位置不受新消息影响。

手机端沿用正文上、助手下的结构，章节导航由菜单打开。普通状态保持紧凑，查看完整对话可从底部展开为接近全屏的对话视图；返回恢复正文位置。软键盘弹出后输入框保持可见，工具行允许换行。

## 4. 对话与发送

作品没有对话时可直接输入；首次发送先自动创建持久化对话，再发送消息。创建成功但发送失败时保留对话 ID、原输入和幂等键，重试不重复创建。仅浏览页面不产生空对话。

新建按钮进入独立空白对话，首次发送再持久化；已有未发送输入按对话或新对话草稿分别保留。首次输入可生成标题。刷新后恢复最近访问的对话；归档对话只读，需恢复后才能发送。

输入区不提供“讨论 / 审阅 / 修改”模式。助手依据用户指令和对话历史决定查阅、分析、生成建议，允许同一轮组合完成。快捷提示只填入指令，不设置隐藏模式，不直接发送。

编辑器当前章节默认作为本轮优先参考，显示“优先参考：章节标题 · 已保存 vN”，可以移除或恢复。无参考时不显示额外说明，快捷提示仍可使用。用户明确指定其他章节时，指令优先；参考章不自动成为修改目标。具体协议见 [统一助手上下文](unified-assistant-context.md)。

Enter 发送，Shift+Enter 换行；输入法组字时 Enter 不发送。发送中防止重复提交。任务执行时按钮改为“停止”，允许准备下一轮输入但不提交；本期不增加运行中插话或排队发送。

## 5. 章节上下文与草稿

对话属于作品，切换章节继续使用当前对话。发送时固定可选参考章节 ID、已保存版本及后端正文快照，模型仅看到引用提示，按需调用 read_chapter 获取正文。未选择章节时通过 list/search 定位相关材料，再按需读取。

运行中切换编辑器章节不改变已受理的参考；历史用户消息展示当轮参考，修改建议展示实际目标。普通提问不要求读取整章；整章审核和生成修改稿应完整读取相应章节。新修改须在本轮重新读取，其工具结果必须进入后续模型请求。

未保存正文不自动保存，也不传给模型。选中参考章节且有未保存正文时明确显示“助手读取已保存版本，本轮不包含未保存正文”。当前实现生成整章候选稿；支持草稿快照和选中文本范围需要另行扩展。

## 6. 回复与修改建议

助手最终回复直接进入消息列表，不再在另一处重复显示“本次要求 / 最终分析”。执行中仅展示简短真实状态，例如“正在查阅章节”，有可展开的执行详情；中间过程不作为最终回答发布。

每条回复按需附带：

- 来源：展开查看章节、版本与对应证据。
- 修改建议：显示目标章节、修改处数、处理状态及“在正文中查看”。
- 附件：可下载文件。
- 执行详情：默认折叠，承载工具步骤、模型调用、错误细节和 Skill 实际使用情况。

点击“在正文中查看”后在上方正文显示对应差异并定位第一处待处理修改。目标不在当前章时先按现有草稿保护流程切换到目标章，不在错误章节套用建议。用户可以逐条应用、忽略或编辑建议，沿用现有修改导航工具栏。

应用建议只修改草稿；“保存正文”后正式生效。已改变的正文继续进行定位与冲突检查，不强制覆盖。历史消息中的建议入口绑定该消息的 runId / proposalId，不随着最新一轮任务改变。

切换对话、查看其他回复和折叠助手不自动切换当前正文审阅对象。切换审阅对象前保留或处理未保存的建议调整；普通聊天回复不清空当前审阅。新的修改建议生成后提供查看入口，不自动替换正在处理的差异。未处理建议不阻止继续发送消息或生成新候选稿；打开、切换建议时沿用草稿与建议调整保护。

## 7. 运行状态

| 状态 | 展示与操作 |
| --- | --- |
| 空对话 | 简短说明助手按需查阅、分析或提出建议；可直接输入 |
| 发送中 | 发送按钮显示提交状态；保护输入直到受理成功 |
| 执行中 | 简短状态与停止按钮；可编辑下一轮草稿 |
| 连接中断 | 提示正在重连并查询状态；不把网络中断当成任务失败 |
| 成功 | 最终回复、来源、建议或附件进入当前轮次 |
| 失败 / 停止 | 保留本轮输入和真实状态，符合后端条件时提供重试本轮 |
| 其他对话运行中 | 提示作品有任务正在执行；允许浏览和准备输入 |
| 刷新恢复 | 恢复当前对话及真实活动任务，不重复发送 |

## 8. 前端改造范围与验收

Workspace 改为两列布局。统一助手放入 writingColumn 底部，删除旧助手 tab、右侧 AgentPanel 挂载以及移动端右侧助手入口。调整 ConversationPanel，或拆分为 WritingAssistant、ConversationMessages、AssistantComposer、ConversationPicker、SkillPicker。

对话、运行状态、输入草稿在工作区层持续存活，折叠只控制显示，不通过卸载组件实现。将正文审阅选择从“当前最新 run”中独立出来，显式存储选中的建议与目标章。复用现有 Conversation API、useRun、SkillLibrary、来源查看和 Proposal 审阅能力；自动创建对话和消息受理继续使用各自真实接口，不能用前端虚构对话 ID。

旧 useAgentTask 不再承担统一助手发送与历史查询职责。旧入口组件、样式和测试根据依赖检查删除；后端旧接口是否移除可另行清理，不影响本次前端方案，不建设兼容入口。

验收重点：桌面无右侧助手与两个模式 tab；底部连续聊天、历史恢复和 Skill 可用；切章不丢对话、不改变活动任务目标；折叠不丢输入和运行状态；发送只发生一次；保存失败不发送；历史建议绑定正确章节与版本；普通聊天不覆盖正文审阅；手机端输入框和键盘布局可用。
