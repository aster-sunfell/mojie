# 统一助手与按需上下文

日期：2026-10-12。替代新 Conversation 入口手动选择 CHAT / CHAPTER_REVIEW / CHAPTER_EDIT 的规则，旧讨论 CHAT 已移除；独立章节任务保留。

## 消息与参考

客户端提交 content、clientRequestId、expectedConversationSeq、skillMentions，以及可选 contextChapterId/contextVersion；不提交 taskType 时使用 ASSISTANT。当前编辑器章节默认提供优先参考，允许移除、恢复，无参考也可发送。快捷提示只填文字。

接收事务检查章节归属和版本，保存 context_chapter_id/context_version/context_content；该快照与修改目标分开。模型首个请求只包含参考 ID 与版本，不注入正文。切换编辑器章节不改变正在运行的参考；失败重试复用原参考快照。未知受理结果重试沿用原请求及幂等键。

正文始终使用已保存版本；有未保存正文时明确提示，不自动保存。草稿快照不是本次能力。

## 执行与检索

依据用户指令与历史决定讨论、审核或修改，允许混合执行。明确指定章节优先于编辑器参考。“这一章”使用本轮参考，指代不明时询问。相关时优先读取参考；其他问题通过 list/search 定位，按需 read，不默认读取整部作品。

普通提问可直接完成，携带参考不强制完整读章。搜索默认 ALL_CHAPTERS；BEFORE_TARGET 可用参考作为位置锚点。首个搜索仍固定章节版本视图，参考章采用受理时版本，其他已读章采用首读版本，后续分页与读取保持一致。搜索摘要用于定位，证据不足时读取原文；整章审核应完整读取对应章。

作品标题通过无参数工具 `read_project({})` 按需读取，返回 `{projectId, title}`。作品范围取自本轮 `ToolContext`，不接受模型指定其他作品；查询仅返回未删除作品，不依赖章节或设定存在。讨论书名、命名或作品身份时读取，普通章节讨论不强制调用，也不在首轮消息中自动注入标题。作品标题属于任务数据，不能覆盖系统规则。

本轮首次成功读取后缓存作品元数据，运行中改名不改变本轮后续读取；下一轮重新读取已保存标题，历史结果不能作为当前书名的可靠来源。读取结果沿用工具执行记录、后续模型请求与预算，无需作品版本字段或数据库迁移。尚未读取的已删除作品返回 `RESOURCE_NOT_FOUND`，查询超时返回 `READ_TIMEOUT`，停止与截止时间沿用运行机制。

## 修改建议

普通统一轮次具备 propose_chapter_edit 与 propose_setting_edit 能力，根据用户需求调用；作者明确要求只分析时不生成候选稿，输入区不设置模式开关。两种工具支持 CREATE 和 UPDATE；UPDATE 要求真实 ID 和读取版本，CREATE 提交标题与正文（设定还需类型），省略 ID 和版本。实际目标可以与参考不同，也可在没有参考的轮次通过检索确定。

正文必须在本轮完整读取，结果成功进入后续模型请求才能生成建议。同一工具批次 read + propose 会拒绝尚未提供给模型的正文，允许下一次模型请求纠正。候选稿基准来自服务端已读缓存，工具不能自报基准内容；版本不符或目标未读会返回可恢复错误。

候选稿携带实际目标 ID、版本、基准正文；完成事务检查完整正文进入最终请求、成功建议步骤与最终回复，再原子发布。一轮最多 8 份候选稿，正式内容在作者审阅保存后改变。失败、取消不发布候选稿。用户按现有差异流程应用、保存，仍校验冲突并保护草稿。

## 存储与展示

V10 新增可选参考快照列，数据库外键保证章节归属与版本存在，ASSISTANT 不要求预先指定修改目标。历史类型和原约束保留，旧请求幂等摘要保持原格式。

Run 详情返回 contextChapterId/contextVersion 描述当轮参考，proposals 数组描述全部建议；兼容字段 targetChapterId/baseVersion 来自第一份建议。消息旁展示参考，建议卡片展示实际修改章。章节任务列表在有候选稿时按实际目标筛选，无候选稿时可按参考筛选。

Skill 自动发现、预算、历史压缩、SSE、停止和对话隔离沿用现有能力。历史压缩保留当前轮工具结果，历史读章不能替代本轮修改证据。

设定版本、修改建议与审阅保存见 [章节与设定修改建议](setting-edit-proposals.md)。
