# 连续对话与 Skill 工程设计

实现依据：Conversation_and_Skills_PRD_v0.1。原有 api → service → repository 边界保持有效。

- Conversation 是持久化隔离边界；产品消息只展示原始输入与终态回答。上下文读取协议消息，保留提供方内容块和完整工具组。失败轮次只复用完整组。
- 新入口默认 ASSISTANT，不预先区分讨论 / 审阅 / 修改；参考章节可选，模型按需 list/search/read，候选稿携带独立目标与基准版本，完整正文证据须在生成建议和最终请求中出现。旧任务类型与独立 Run 入口保留兼容，详见 [统一助手上下文](unified-assistant-context.md)。
- 接收按作品、对话顺序加锁，在同一事务提交序号、消息、Run、Skill 版本目录与活动槽。终态通过数据库触发器同步展示消息和释放对话槽，兼容取消和重启恢复。
- 模型配置固定在对话；每次逻辑请求持久化完整快照及来源消息 ID，不保存鉴权信息。压缩保留原协议记录，摘要版本独立保存。
- 完整不可变包由文件存储保存，PG 保存清单与引用；文件持久化/原子移动先于 READY 数据库提交。未知提交不删除包。
- Skill 仅动态加载角色、方法与参考文本；项目基础工具由当前任务提供，Skill 不能授予权限。不执行上传代码，无独立 Skill 执行器或运行时镜像。见 [上下文 Skill 设计](context-only-skills.md)。
- 包、产物使用受保护 ID 下载及 attachment/nosniff 响应，不能直接同源执行 HTML/SVG。

接口、实现验证与未签收项随代码同步记录；真实模型及独立恢复验证未完成前不宣称完整验收。

## 设置、引用与渐进加载（2026-10-12）

- 作品列表页和写作工作区均可打开全局“设置 → Skill”；作品设定仍独立管理人物、世界观和写作约束。设置覆盖当前界面，保留正文草稿、对话及运行任务。
- Skill 库提供名称/用途搜索、状态筛选、Markdown/ZIP/目录导入、启停、版本发布、删除与高级文件管理；修改后刷新助手可引用目录。
- 输入区 Skill 按钮打开引用列表，或输入 `$` 搜索；选择后插入 `$名称`，含空格/标点的名称使用 `$[名称]`。发送 `skillMentions: [{skillId, name}]`，删除引用同步删除结构化记录。稳定 ID 保留改名前已插入的引用。
- 接收事务验证显式引用并锁定当前版本，始终绑定所有已启用 Skill 的摘要目录。初始请求仅包含摘要与显式引用 ID，不读取指导全文。
- 模型统一调用 `read_skill` 渐进读取。显式引用必须成功读取且正文进入后续模型请求，才能执行其他工具或完成任务；附件和脚本仍按需使用。自然语言明确指定同样要求读取；名称歧义由助手澄清。
- 无显式引用时按任务匹配描述；没有合适 Skill 可以直接回答。显式引用不会关闭其他 Skill 的发现能力。旧引用作为历史任务上下文，不成为后续轮次的强制配置。
- 删除对话发现开关和固定接口。V13 移除 `discovery_enabled`、`tb_conversation_skill`，在消息上保存结构化引用；已有消息、不可变包和 Run 版本记录保留。重试使用原消息引用与显式版本快照。
- 执行详情仅显示实际加载的 Skill，区分用户指定、助手发现，以及“已加载”和“已供模型使用”。

机制参考：[OpenAI 官方 Skill 文档](https://learn.chatgpt.com/docs/build-skills#how-codex-uses-skills)。
