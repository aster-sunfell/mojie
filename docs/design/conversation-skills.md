# 连续对话与 Skill 工程设计

实现依据：Conversation_and_Skills_PRD_v0.1。原有 api → service → repository 边界保持有效。

- Conversation 是持久化隔离边界；产品消息只展示原始输入与终态回答。上下文读取协议消息，保留提供方内容块和完整工具组。失败轮次只复用完整组。
- 新入口使用 CHAT / CHAPTER_REVIEW / CHAPTER_EDIT；旧入口保持独立章节任务、8/12 预算。新入口预算存入 Run 配置，章节证据仍须在本轮最终请求中出现。
- 接收按作品、对话顺序加锁，在同一事务提交序号、消息、Run、Skill 版本目录与活动槽。终态通过数据库触发器同步展示消息和释放对话槽，兼容取消和重启恢复。
- 模型配置固定在对话；每次逻辑请求持久化完整快照及来源消息 ID，不保存鉴权信息。压缩保留原协议记录，摘要版本独立保存。
- 完整不可变包由文件存储保存，PG 保存清单与引用；文件持久化/原子移动先于 READY 数据库提交。未知提交不删除包。
- SkillExecutor 是独立服务；服务端固定运行环境，上传内容只能在无网络、只读包、非特权、受资源限制的执行容器中运行。
- 包、产物使用受保护 ID 下载及 attachment/nosniff 响应，不能直接同源执行 HTML/SVG。

接口、实现验证与未签收项随代码同步记录；真实模型及独立恢复验证未完成前不宣称完整验收。
