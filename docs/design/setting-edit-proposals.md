# 章节与设定修改建议

日期：2026-10-12。状态：第一期已实现，每轮最多一份建议，目标为一个章节或一条已有设定。

## 对话与工具

统一对话默认使用 ASSISTANT，根据作者要求查阅、分析或提出修改建议，不增加章节/设定任务模式。章节工具命名为 `propose_chapter_edit`，设定工具为 `propose_setting_edit`，不提供 `propose_edit` 别名。

设定工具参数为 settingId、expectedVersion、proposedType、proposedTitle、proposedContent、reason。本轮先调用 read_settings 完整读取目标，工具结果进入后续模型请求后才可提交；服务端从已读取缓存取基准类型、标题、内容和版本，不接受模型自行提供基准。每轮候选状态由两种目标共享，不能生成第二份建议。完成事务检查完整设定读取是否进入最终模型请求，并保存对应建议。生成建议不会修改正式内容。

输入区提供“仅分析”选项，提交 analysisOnly 标志。后端在该轮移除两个修改建议工具，工具执行层再次检查标志；重试保留原轮次标志。未勾选时，作者明确要求只分析仍由提示词要求不生成候选稿。

修改设定不自动修改关联章节。作者要求同时修改多个目标时，本期每轮一份建议，应说明限制并分轮处理；多目标建议、新建设定、删除设定均留待后续。

## 数据与保存

V12 为设定增加 version 和不可变修订历史；已有设定按当前内容回填 v1。新增、手动保存、应用建议分别记录 CREATE、MANUAL、AGENT 来源。修订保存类型、标题、正文、版本、来源和 proposalId，最近 50 版可以在设定窗口查看。

现有建议表扩展 targetType 和 targetSettingId，数据库约束确保 CHAPTER 与 SETTING 两种目标互斥，并检查作品归属、基准修订存在、设定类型及长度。设置类型限 CHARACTER/WORLD/RULE，标题最多 80 码点，正文最多 2000 码点。

手动 PATCH /settings/{id} 必须提交 expectedVersion。审阅设定通过 PUT /edit-proposals/{id}/setting 提交最终类型、标题、正文及基准版本；在同一个事务中锁作品、建议及目标设定，校验正式版本，保存修订并将建议标记 APPLIED。版本变化则提交 CONFLICTED 状态，返回 409，不覆盖正式设定。已应用建议的重复保存不会再次递增版本。运行任务期间不修改设定。

## 界面与草稿

对话卡片展示实际设定目标，点击“在设定中查看”打开原作品设定窗口。类型、标题、正文分别展示修改前后内容，可逐项或全部应用、忽略，再编辑下方草稿。应用只更新草稿，保存后生效，未应用部分一并忽略；可以直接忽略整份建议。

关闭、切换设定或取消编辑会保护未保存草稿。设定建议不切换章节，也不清空正在审阅的正文或章节草稿。历史建议入口绑定对应 proposalId；处理后重新打开会展示真实状态及当前设定。旧基准建议显示冲突，禁用应用和保存，仍可忽略。

## 移除旧讨论

不再接受 taskType=CHAT，不保留旧讨论专用分支或工具过滤规则。V12 将已有 CHAT 任务迁移为 ASSISTANT，保留对话消息和执行记录，并从数据库任务类型约束中移除 CHAT。独立章节任务接口不在本次移除范围。
